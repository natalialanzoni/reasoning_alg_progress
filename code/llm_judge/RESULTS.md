# Behaviour counts — results

Generated by `code/llm_judge/behaviour_table.py` from
`out/judge_whole_gemini.jsonl` (2,560 records, 2,498 usable) plus deterministic
markers over the same traces. Sample: the four `fig_mechanism` models, 40
competition problems, k=8, CoT only.

**Two instruments, on purpose.** Verification comes from the LLM judge
(gemini-2.5-flash, whole trace). Backtracking does NOT — two judges correlate
only +0.52 on it (exact agreement 9/40) and support opposite lever directions, so
it uses explicit abandonment markers, which are reproducible and auditable.

**Backtracking excludes memory-recall context** (see below). Without that
exclusion the algorithm lever reads 5.49x instead of 3.32x.

## The memory-recall confound, and why backtracking excludes it

GLM 5.3 spends much of its trace trying to REMEMBER whether it has seen the
problem — *"let me reconsider the memory one final time... I believe the answer
is 63"*. That fires `let me reconsider` without any path being abandoned, so it
inflates backtracking for one model only.

Reproduce with `python code/llm_judge/recall_check.py`.

**Only the pre-computation column is a valid test.** A claim made after the model
has computed something is post-hoc restatement, not memory — a model that derives
62 and then writes "yes, I recall the answer is 062" is not remembering anything.
The restriction is to claims appearing before the first equation with a computed
right-hand side, where the number cannot yet have been derived.

| model | attempts /10k tok | % traces attempting | pre-computation claims | matching gold |
| --- | ---: | ---: | ---: | ---: |
| gpt-oss-20b | 0.18 | 11% | 0 | — |
| gpt-oss-120b | 0.16 | 10% | 1 | 0/1 (0%) |
| GLM 5.2 | 0.10 | 13% | 0 | — |
| GLM 5.3 | **9.86** | **54%** | **84** | **0/84 (0%)** |

**Zero of 85 pre-computation claims match gold, across all four models.** With
n=85 that bounds a true recall rate at roughly 1 in 85 rather than proving it is
exactly zero.

For contrast, the naive test — scoring every recall claim regardless of position —
returns 16–40% and ranks GLM 5.2 highest at 40%, despite GLM 5.2 making no real
recall attempts at all. That number is not reported anywhere here because it
cannot be read correctly.

**Two findings, and they are separate.** Attempt rate is wildly model-specific:
GLM 5.3 tries to recall in 54% of traces at ~60–100x the rate of the others, and
cites 2024 most (1,054 times), then 2025, 2020, 2014 — never 2026, because its
training predates the benchmark. Success rate is zero for everyone. So this is
confabulated retrieval, not contamination.

Caveat on the method: "before computation" is a heuristic — the first `=` with a
numeric right-hand side, `\boxed`, `\frac`, or an explicit compute/calculate. A
model reasoning quantitatively in prose first would slip past it.

**The exclusion.** A backtracking marker hit is dropped when recall language
appears within 400 characters. It is well targeted — 578/1,346 hits removed for
GLM 5.3 (43%), and 2/277, 1/208, 0/55 for the others. Hand-check of 20 hits per
model before the fix: GLM 5.2 ~14/14 genuine, GLM 5.3 ~7/20, which independently
puts the corrected algorithm lever near 2.5x against the measured 3.32x.

## Reading this

**Scale (20B → 120B): less deliberation, full stop.** Verification falls per
trace (0.48×) *and* per token (0.70×); backtracking falls 0.39× per word. The
bigger base model needs less search, not just fewer words to express it.

**Algorithm (5.2 → 5.3): compression, not less reasoning.** The trace collapses to
0.29× its length. Verification count falls 1.38× while length falls 1.66×, so
density *rises* 1.21× — verification is preserved relative to length rather than
increased. Backtracking rises 3.16× per 10k tokens (5.49× before the recall exclusion).

So the honest summary is: **backtracking density rises (3.16×), verification
density is roughly flat, and both fall in absolute terms because the trace got
shorter.** Search behaviour amplified; checking behaviour merely kept pace.

## Robustness

The backtracking result is not a formatting artifact. GLM 5.2 writes heavy LaTeX
(413 `$` per 10k chars) and 5.3 almost none (7), which inflates 5.2's character
count — the same trap as README run-hygiene item 11. Re-normalising:

| lever | /char | /token | /sentence | /word |
| --- | ---: | ---: | ---: | ---: |
| Scale 20B→120B | 0.41× | 0.45× | 0.51× | 0.39× |
| Algorithm 5.2→5.3 (no recall exclusion) | 5.15× | 5.70× | 5.56× | 5.49× |

Neutral controls do not move with it: `the` 0.39×, digits 1.28×, `=` 1.23×,
sentence density 1.00×. A general terseness effect would move those too.

Including `contradiction` in the marker set changes magnitude (3.51× instead of
5.49×) but not direction; it is excluded by default because in mathematics it is
usually a proof technique rather than an abandoned path.

## What these numbers are not

* **Absolute counts are instrument-dependent.** Gemini and sonnet-4.5 differ ~2.5×
  in magnitude on verification even where they agree on ranking. Compare models
  within this table; do not quote a count as "GLM 5.2 verifies 13 times".
* **Backtracking here means STATED abandonment.** A model that silently drops an
  approach is not counted.
* **5.2 → 5.3 confounds everything that changed between releases** — RL recipe,
  data, output format. "Denser backtracking in shorter traces" is the
  measurement; attributing it to RL is an interpretation.
* **Verification's 1.21× is weak.** With n≈305 per model and wide per-trace
  spread, treat it as "unchanged" unless a confidence interval says otherwise.
